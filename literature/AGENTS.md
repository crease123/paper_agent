# 论文库管理规范

## 目标

`literature/` 面向 Agent 检索和增量判断。概要必须短、密、可比较；默认先读概要，只有必要时才读全文。

## 如何下载

- 调用 `mineru-fetch-markdown` 技能下载论文为md文档。

## 文件如何管理

- 按金字塔原则分类归档：研究领域 → 方法类别 → 细分问题。每个层次都是一个文件夹。
- 分类树与**收录边界**见 `taxonomy.md`：每个节点都有「上界（收录）/ 下界（不收录）」，下界里带 `→ 归入` 路由指针。归档新论文时按它选位置；放不下就新建节点并更新分类树。
- **边界的唯一真源是 `taxonomy.md`**；各 `category_summary.md` 的 `**边界**` 行是它的投影，供该分类内就地阅读；两者不一致时以 `taxonomy.md` 为准，改动边界时必须同步。
- `taxonomy.md` 的篇数按各分类下的 `*_summary.md` 计数（不含 `category_summary.md`），归档后必须同步。
- 每个细分类文件夹下必须有 `category_summary.md`。
- 论文文件夹只保留：`<论文名>.md`、`images/`、`<论文名>_summary.md`。

## `<论文主文件名>_summary.md`规范

概要使用简体中文，优先表格和短句，避免复述背景。建议控制在 **300–800 字**，只保留影响检索和纳入决策的信息：

```markdown
## 结论
一句话说明论文做了什么、效果如何。

## 价值与增量
- 对本项目的价值：
- 相比已有论文新增/重复/冲突：

## 局限

## 证据
章节、表/图、页码或链接；区分论文事实、推断和本项目验证。
```

## `category_summary.md`规范

- 语言要简洁明了

```markdown
# 分类名称

**边界**：收录什么，不收录什么。

## 覆盖情况
问题、数据、方法、指标、空白；每项用短句。

## 论文比较
| 论文 | 方法/数据 | 结果 | 局限 | 增量/价值 |
|---|---|---|---|---|

## 结论与空白
只写跨论文的共识、分歧和未解决问题。

## 索引
- [论文概要](相对路径)
```

## 归类决策流程

决定一篇论文放哪里之前，必须完成以下步骤，顺序不可颠倒：

1. **列候选**：读 `taxonomy.md` 的节点上界/下界，列出 **2–3 个**候选节点。只列一个候选视为未完成。
2. **比对边界**：对每个候选，引用其**上界/下界原文**，逐条判定「命中上界 / 命中下界」。命中下界即排除。候选名不得自行发明，必须是 `taxonomy.md` 里已有的节点；确实都不合适才新建节点。
3. **查已有概要**：读目标分类的 `category_summary.md`，以及主题相邻分类的 `category_summary.md` 与相关单篇 `_summary.md`，逐项比较问题、数据、方法、指标、结果、反例或修正。**不能只看标题或关键词。**
4. **识别跨类重叠**：若论文同时命中两个节点的上界，按**主贡献**归类，并在单篇概要的「分类/标签」与相关节点的「跨类指引」里写明交叉检索提示。
5. **写下决策表**：交付说明中必须包含「候选节点 / 引用的边界原文 / 判定 / 理由」四列。只给结论不算完成。

## 归档时必做

1. 生成单篇概要；
2. 更新所属分类的 `category_summary.md` 和索引；
3. 更新 `taxonomy.md`（节点、篇数、必要的跨类指引）；
4. 用 `未知`、`未报告` 或 `未验证` 标注缺失信息，不猜测。

概要是检索入口，不是全文替代品；所有事实、推断和本项目验证必须明确区分。
